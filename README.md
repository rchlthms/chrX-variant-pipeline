# chrX Polyploid Variant Calling Pipeline

A Snakemake workflow for identifying single-nucleotide variants (SNPs) on chromosome X from paired-end whole-genome sequencing (WGS) data. The pipeline supports diploid and polyploid samples and uses configurable ploidy for variant calling.

## Features
- Quality control, adapter trimming and read deduplication with **fastp**
- Read alignment with **BWA-MEM**
- Extraction of chromosome X reads
- Read-group assignment and duplicate marking with **GATK**
- Variant calling with **GATK HaplotypeCaller**
- Automatic creation of missing reference genome indexes and sequence dictionary
- Addition of reference genome information to the VCF header
- Optional diploidisation of polyploid variant calls

## Requirements
- Conda / Mamba
- Snakemake (tested with version 8.11.3)
- A reference genome FASTA file
- Paired-end FASTQ files for each sample

The required bioinformatics tools are specified in the Conda environment files in `envs/`. Snakemake creates and uses these environments when the workflow runs.

## Configuration
```text
chrX-variant-pipeline/
├── Snakefile
├── config.yaml
├── envs/
│   ├── alignment.yaml
│   ├── fastp.yaml
│   ├── gatk.yaml
│   └── vcf.yaml
├── data/
│   └── raw_fastq/
├── results/
├── logs/
└── README.md
```

- `Snakefile`: defines the workflow and its rules.
- `config.yaml`: contains the reference genome path and analysis settings.
- `envs/`: defines the software environments used by the workflow.
- `data/raw_fastq/`: contains the input FASTQ files.
- `results/`: contains intermediate files and final variant calls.
- `logs/`: contains logs generated by individual workflow steps.

Edit `config.yaml` to specify the reference genome and analysis settings.

Example:

```yaml
reference_genome: "/path/to/reference_genome.fa"
reference_name: "GRCh38"
ploid: 2
threads: 8
java_mem: "16g"
```

| Setting | Description |
|---|---|
| `reference_genome` | Path to the reference genome FASTA file. |
| `reference_name` | Reference genome identifier added to the output VCF header, for example `GRCh38`. |
| `ploid` | Sample ploidy supplied to GATK HaplotypeCaller. Values greater than 2 trigger the pipeline's diploidisation step. |
| `threads` | Number of threads used by applicable tools. |
| `java_mem` | Maximum Java heap memory requested for GATK, for example `16g`. |

Use the full path to the reference FASTA so the workflow can locate it reliably.

## Input data

The workflow expects paired-end FASTQ files in `data/raw_fastq/`.

Each sample must have two files named using the following pattern:

```text
data/raw_fastq/SAMPLE_1.fq.gz
data/raw_fastq/SAMPLE_2.fq.gz
```

Replace `SAMPLE` with the sample identifier. The identifiers for each pair must match exactly.

For example:

```text
data/raw_fastq/SRR23562792_1.fq.gz
data/raw_fastq/SRR23562792_2.fq.gz
```

The workflow discovers samples from files matching `*_1.fq.gz` and expects the corresponding `*_2.fq.gz` file to exist.

### Reference genome indexing

The pipeline checks for the reference files required by its alignment and variant-calling steps. If the required outputs are missing, Snakemake runs the relevant rules to create them:

- BWA index: `.amb`, `.ann`, `.bwt`, `.pac` and `.sa`
- Samtools FASTA index: `.fai`
- GATK sequence dictionary: `.dict`

These files are created alongside the configured reference FASTA. The account running the workflow must therefore have permission to write to the reference genome's directory when any of these files need to be created.

Existing, up-to-date index files are reused by Snakemake rather than regenerated unnecessarily.

## Running the pipeline
You must have your conda/mamba/snakemake environment active before running the pipeline.

Run these commands from the repository root.

### 1. Check the workflow

Perform a dry run to inspect the jobs Snakemake plans to execute without running them:

```bash
snakemake --dry-run --cores 1 --use-conda
```

### 2. Run the workflow

Run the pipeline using eight available cores:

```bash
snakemake --cores 8 --use-conda --printshellcmds
```

Adjust `--cores` to match the resources available to you. On a shared computing cluster, request appropriate resources through the cluster's job scheduler before running the workflow.

On the first run, Snakemake may need to create the Conda environments and reference index files. Subsequent runs can reuse existing environments and up-to-date outputs.

## Output files

Intermediate files are organised under `results/` by processing stage:

- `results/fastp/`: trimmed FASTQ files and fastp reports.
- `results/bam/`: aligned, chromosome X-filtered and processed BAM files, along with related metrics and indexes.
- `results/vcf/`: variant call files.

The final compressed VCF depends on the configured ploidy:

- **Diploid samples (`ploid: 2`):** `results/vcf/SAMPLE_chrX_with_reference.vcf.gz`
- **Polyploid samples (`ploid > 2`):** `results/vcf/SAMPLE_chrX_diploid.vcf.gz`

The VCF files are compressed with bgzip and indexed with tabix where specified by the workflow.

Workflow logs are written under `logs/`, organised by processing step.

## Important notes

- The analysis is currently hardcoded to chromosome `chrX`.
- The pipeline expects paired-end reads.
- The configured ploidy is passed to GATK HaplotypeCaller.
- For ploidy greater than 2, the workflow applies its diploidisation step to the resulting chromosome X calls.
- The pipeline's diploidisation step applies simplified genotype-conversion logic; inspect and validate the resulting genotypes for your scientific use case.
- Reference index files are generated beside the reference FASTA, so ensure the relevant directory is writable when indexing is required.

## Troubleshooting

**No FASTQ files found**

Check that the input files are in `data/raw_fastq/` and that their names end in `_1.fq.gz` and `_2.fq.gz`.

**FASTQ processing fails with an unexpected end-of-file error**

Check that the FASTQ files are complete and not truncated. For gzip-compressed files, run:

```bash
gzip -t data/raw_fastq/SAMPLE_1.fq.gz
gzip -t data/raw_fastq/SAMPLE_2.fq.gz
```

A successful check produces no output. An error indicates that the compressed file may be damaged or incomplete.

**Reference index creation fails**

Check that the reference FASTA exists, that the configured path is correct, and that you have permission to create index files in its directory.

**A workflow step fails**

Inspect the corresponding log file under `logs/` and review the error reported by the tool. You can also rerun the workflow with `--printshellcmds` to see the commands Snakemake executes.
